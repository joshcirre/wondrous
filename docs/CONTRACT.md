# Wondrous MVP contract
Laravel 13, React 19 + Inertia, Reverb, Verbs; database-backed defaults; Redis optional. 1v1, 6 units each, 8x8. No paid or permanent combat stats. Full shared standard roster (warden,ranger,knight,arcanist,cleric,rogue,pikeman,herald). Four specialists (pyromancer,frostweaver,druid,revenant) available as loans so new players have access. Players may prioritize up to 4 owned specialists in personal loadout; fill unused slots with match loans. Alternate visible draft picks from 3 random offers; each player picks 6 distinct characters from own pool. Player deployment rows y 6,7 (host), y 0,1 (guest); complete before battle. One unit activated per player turn: may move once, attack OR skill once; end turn manually. Actions cause recovery on future own turns. Defeat all units for victory; herald provides nearby armor aura and killer team gets mana on herald defeat.

Canonical character ids: warden,ranger,knight,arcanist,cleric,rogue,pikeman,herald,pyromancer,frostweaver,druid,revenant.

Server JSON state shape (engine): phase: lobby|draft|deployment|battle|finished, players: [{id:number,name:string}], host_id:number, turn_player_id:number|null, turn_number:number, draft_picks: Record<string,string[]>, offers: Record<string,string[]>, pool: Record<string,string[]>, units: Unit[], ready: number[], active_unit_id:string|null, moved:boolean, acted:boolean, winner_id:number|null, log: [{turn:number,text:string}], reward_candidates:Record<string,string[]>.
Unit: {id:string,character_id:string,owner_id:number,x:number,y:number,hp:number,max_hp:number,mana:number,max_mana:number,facing:string,recovery:number,cooldown:number,statuses:Record<string,number>}. Cardinal facing north/east/south/west.
Character definition: {id,name,title,role,standard:boolean,color,description,hp,mana,attack,armor,move,range,accuracy,block,skill:{name,description,cost,cooldown,range,target:string},passive:string}.
Engine action names: join (player supplied), draft {character_id}, deploy {unit_id,x,y}, ready {}, move {unit_id,x,y}, attack {unit_id,target_id}, skill {unit_id,target_id?}, face {unit_id,facing}, end_turn {}, resign {}.

HTTP planned: GET / (Lobby page; guest auth screen); POST /register, /login, /logout; POST /games {name,ranked}; GET /games/{code} -> Game page; GET /games/{code}/state -> {game,catalog,viewer_id}; POST /games/{code}/actions {type,version,...payload}; GET /collection; POST /collection/loadout {cards:[]}; POST /collection/pull {}; POST /games/{code}/claim {character_id}; GET /rankings.
Game public object: {id,code,name,ranked,version,state,created_at}; catalog keyed by id. Inertia props {auth:{user:{id,name,rating,currency,wins,losses}},catalog,game?,games?,...}. All mutations require authenticated sessions+CSRF; game mutation serialized + version precondition; server validates player and action, records randomness, never client random authority. Private channel game.{id} broadcasts .game.updated {version}; only participants access; poll fallback. Lobby public lobby channel broadcasts .lobby.updated only non-sensitive summary.


## Correspondence and replay additions

`POST /games` accepts optional `time_control: "live" | "correspondence"` (defaults live). Correspondence forces `ranked=false`. Game JSON adds `time_control` and `turn_due_at: ISO8601|null`; both values also appear in persisted state frames. No lobby deadline; each draft pick and battle turn has 24 hours; deployment has one shared 24-hour cutoff for each unready player. Partial actions never renew a deadline. Timeouts set `phase=finished`, `finish_reason=timeout`, `expired_player_ids:number[]`, and `winner_id` (null for both-unready deployment draw). Timeout audit/event actors are null. Scheduler command `games:expire` runs every minute; reads/actions also expire overdue games atomically. A deadline-expired command returns409 after committing the timeout.

Lobby props add `active_games:[{code,name,time_control,phase,turn_player_id,turn_due_at,ready,host_id,players}]`. Compatibility `active` contains only the active live game's code or null. Public lobby games and recent games include time_control; recent adds draw:boolean.

`GET /games/{code}/replay-data` returns `{game,catalog,viewer_id,frames:[{version,actor_id:number|null,action,created_at,state}]}`. `GET /games/{code}/replay` renders Inertia `Replay` with those same props. Both require a finished match and participant access. All replay frames and the top-level replay game state omit offers, pool, loadouts, and reward_candidates entirely. Full deployment units are revealed after completion; command payloads are omitted.


`GET /replays` renders authenticated Inertia `ReplayArchive` with `{result, matches}`. `matches` is a Laravel paginator with 12 rows per page. Each row contains `{code,name,ranked,time_control,players,winner_id,finished_at,updated_at}` and no board or private draft data. Only the viewer's finished games are included, ordered by updated_at descending then id descending. Optional `?result=all|won|lost|draw` filters outcomes and persists across page links. `finished_at` uses settled_at, falling back to updated_at for legacy games. Lobby recent matches also sort by updated_at.
